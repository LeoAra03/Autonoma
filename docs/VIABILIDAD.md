# Viability

Autonoma measures one question very well: *is this project professionally
built?* It answers that question with gates, a scorecard, and a ladder.

It does **not** answer the question that matters more: *should this project
exist?*

That question is not a measurement. No scorecard in the world tells you
whether the thing you are building is worth building, whether anyone will use
it, whether the market wants it, or whether the cost of maintaining it will
ever be justified by the value it delivers. Viability is an argument, and it
is made by humans, in reviews, with their eyes on the users.

So here is where the boundary sits:

- **Autonoma knows quality.** It knows whether the code builds, whether the
  tests pass, whether the tree is clean of secrets, whether the docs are
  honest, and whether the project can be handed to someone else. That is what
  the ladder measures, and it is a real, useful, checkable thing.
- **Autonoma knows nothing about market fit.** A project can sit at S4 —
  tested, documented, secured, handed over — and still be a project nobody
  needs. Autonomy of execution is not autonomy of direction.

The value of the ladder is that it removes the *excuses*. When a project is
not viable, the question this tool answers is no longer the blocker: quality
was never the problem, and now that is visible. When a project *is* viable,
this tool is what lets it reach the hands of a team without the usual
slowdowns of trust, triage and "I think it works".

In short: Autonoma will not tell you your product is good. It will make sure
nobody can claim your engineering is the reason it failed.
